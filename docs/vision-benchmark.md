# Vision runtime benchmark — Intel Iris Xe

Profile measured on Windows, Intel Iris Xe, PyTorch CPU 2.5.1, OpenVINO 2026.3,
with YOLO and SDA-GCN on OpenVINO GPU and MediaPipe Pose on CPU. Reports are
generated by `tools/benchmark_vision_runtime.py` into ignored `data/` JSON files.

## One-camera target sweep

Twenty-second normal-video runs used the shared sequential candidate. Full
70-second fall-video runs verified logical correctness.

| Target | Actual Hz | Normal drops | Fall events (expected 2) | Verdict |
|---:|---:|---:|---:|---|
| 5 | 5.000 | 0 | 2 | Stable/correct |
| 6 | 6.000 | 0 | 1 | Rejected: missed fall |
| 7 | 6.999 | 0 | 1 | Rejected: missed fall |
| 8 | 8.001 | 0 | 0 | Rejected: missed falls |
| 10 | 9.985 | 2 on fall run | 0 | Rejected |
| 12 | 11.940 | 2 | not promoted to full E2E | Rejected: degraded |
| 15 | 14.849 | 6 | not promoted to full E2E | Rejected: degraded |

The 5 Hz selection is therefore a measured model-correctness ceiling for this
fixed video, not a scheduler hard limit. ML constants and thresholds were not
changed to improve throughput.

## Scheduler and camera scale

| Candidate | Cameras | Actual Hz/camera | Input drops/camera | Correctness | Result |
|---|---:|---:|---:|---|---|
| Shared sequential | 2 | 4.985 | 2 | fall 1/2; normal 0 | Rejected |
| Per-camera ordered, unlocked shared SDA-GCN | 2 | ~5.0 | 0 | `Infer Request is busy` | Rejected |
| Per-camera ordered, narrow SDA-GCN lock | 2 | 5.0 | 0 | fall 2/2; normal 0 | Selected |
| Per-camera ordered | 3 | 4.985 | 2 | each fall stream 1/2 | Unsupported on this host |

Selected production architecture: one ordered worker per enabled camera,
per-camera tracker/Pose/session state, shared model/runtime, and a narrow lock
around the OpenVINO SDA-GCN infer request. Two concurrent cameras are the
validated Intel profile.

## Stage latency, selected 2-camera production run

| Camera | Pipeline p50/p95 | Detector mean | Pose mean | SDA-GCN mean |
|---|---:|---:|---:|---:|
| Fall | 63.6 / 115.7 ms | 40.6 ms | 22.1 ms | 48.1 ms |
| Normal | 72.7 / 116.7 ms | 50.8 ms | 21.8 ms | 49.8 ms |

Process CPU time was about 130% of one core across the two-camera run. This is
not whole-system CPU utilization. There were two worker threads, zero overloads,
and zero temporal/input drops.

## Batching

The verified OpenVINO detector artifact has static input shape
`[1,3,640,640]`. A two-frame request failed with an explicit shape mismatch;
sequential processing of a warmed pair averaged 27.8 ms in the isolated test.
Batching was not selected because it would require a new batch artifact and a
separate per-camera tracker/reordering design, with no measured benefit on the
current verified runtime.

## Reference parity

`tools/compare_vision_reference.py` keeps `visionv2/` as the standalone oracle.
On CPU, boxes, poses, model inputs, logits and probabilities were exact
(`max_abs=0`); sample/window IDs and class/event output matched. Standalone
SDA-GCN requires a documented CPU device-safety shim because its native code
uses `Tensor.get_device()`.

On Intel OpenVINO, logical class/event parity held. Observed numerical deltas:

- detector box: at most 1 pixel;
- pose: `max_abs=0.104713` after the altered crop boundary;
- logits: `max_abs=0.195137` after detector/pose input drift;
- probabilities: `max_abs=0.000626`, within `1e-3`;
- predicted class and logical events: equal.

Track IDs are not compared as absolute integers because independent Ultralytics
tracker instances allocate different IDs; track continuity and associated
boxes/poses remain the meaningful comparison.
